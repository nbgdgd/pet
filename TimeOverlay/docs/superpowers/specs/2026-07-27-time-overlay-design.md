# TimeOverlay — оверлей со счётчиком времени в приложении

Дата: 2026-07-27
Пакет: `com.timeoverlay`
Каталог: `D:\AndroidProjects\AniBlaze\TimeOverlay`

## Задача

Маленький оверлей поверх всех приложений показывает, сколько времени идёт текущая сессия
в том приложении, которое сейчас открыто. Форму, размер, цвет и прозрачность настраивает
пользователь. Приложение целиком включается и выключается одним тумблером.

## Решения, принятые при обсуждении

| Вопрос | Решение |
|---|---|
| Что считает таймер | Время в приложении, которое сейчас на переднем плане |
| Сброс при возврате | Сессия с грацией: вернулся в пределах порога — счёт продолжается |
| Изменение формы и размера | Слайдеры в настройках, оверлей пальцем только перетаскивается |
| Содержимое оверлея | Только время |
| Определение текущего приложения | Опрос `UsageStatsManager` раз в секунду |
| UI настроек | Обычные View + Material 3 |

## Архитектура

```
MainActivity (настройки + главный тумблер)
      │  SharedPreferences — единственный источник состояния
      ▼
OverlayService (foreground service, START_STICKY)
 ├── ForegroundAppTracker — опрос UsageStats → имя пакета
 ├── SessionTimer         — чистый Kotlin, грация и сброс
 └── OverlayView          — WindowManager, отрисовка, перетаскивание
```

Настройки применяются вживую: сервис слушает `OnSharedPreferenceChangeListener` и
перерисовывает оверлей без перезапуска.

### SessionTimer — контракт

Вход: `onForeground(pkg: String?, now: Long)` раз в секунду. `null` означает «не в отслеживаемом
приложении» (экран погас, открыт лаунчер, открыты сами настройки).

Выход: `elapsed(now): Long` — миллисекунды текущей сессии, `0` когда сессии нет.

Правила:

1. Тот же пакет подряд — счёт идёт дальше.
2. Смена пакета — старая сессия «паркуется» с отметкой времени, новая стартует с нуля.
3. Возврат к припаркованному пакету в пределах `graceMillis` — счёт продолжается с того же места.
4. Возврат позже грации — сессия с нуля.
5. Припаркованные записи старше грации удаляются.

Хранится карта припаркованных сессий, а не одна запись: цепочка A → B → A должна
восстанавливать сессию A, а не обнулять её.

### Разрешения

| Разрешение | Зачем | Способ выдачи |
|---|---|---|
| `SYSTEM_ALERT_WINDOW` | Рисовать поверх других приложений | `ACTION_MANAGE_OVERLAY_PERMISSION` |
| `PACKAGE_USAGE_STATS` | Узнать приложение на переднем плане | `ACTION_USAGE_ACCESS_SETTINGS`, проверка через `AppOpsManager` |
| `POST_NOTIFICATIONS` (33+) | Уведомление фонового сервиса | Системный диалог |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE` (34+) | Сервис живёт в фоне | Только манифест |
| `RECEIVE_BOOT_COMPLETED` | Автозапуск | Только манифест |

Главный тумблер заблокирован, пока не выданы первые два. Каждая карточка показывает
состояние и кнопку «Выдать».

### Настройки

| Ключ | Диапазон | Дефолт | Эффект |
|---|---|---|---|
| `enabled` | bool | false | Запуск и остановка сервиса |
| `size_percent` | 0–100 | 35 | Размер текста 10–34sp, отступы масштабируются |
| `corner_percent` | 0–100 | 100 | 0 — квадрат, 100 — пилюля |
| `opacity_percent` | 10–100 | 85 | Прозрачность всего оверлея |
| `bg_color` | int | #CC000000 | Цвет фона |
| `text_color` | int | #FFFFFFFF | Цвет текста |
| `grace_seconds` | 15/30/60/120 | 30 | Порог грации |
| `hide_on_launcher` | bool | true | Прятать на рабочем столе |
| `autostart` | bool | false | Запуск после перезагрузки |
| `pos_x`, `pos_y` | int | 24, 200 | Позиция, сохраняется при перетаскивании |

Палитра из восьми готовых цветов плюс ввод своего hex. Наверху экрана — живое превью
тем же классом `OverlayView`.

## Поток данных

1. `MainActivity` пишет в `SharedPreferences`.
2. `OverlayService` получает колбэк изменения и применяет стиль к `OverlayView`.
3. Цикл сервиса раз в секунду: опрос трекера → `SessionTimer.onForeground` → текст оверлея.
4. Перетаскивание оверлея пишет `pos_x`/`pos_y` обратно в prefs при отпускании пальца.

Для отсчёта времени используется `SystemClock.elapsedRealtime` (монотонные часы),
для запроса UsageStats — `System.currentTimeMillis` (того требует API).

## Обработка сбоев

| Ситуация | Поведение |
|---|---|
| Отозвано разрешение на оверлей | Сервис снимает оверлей, гасит `enabled`, шлёт уведомление, останавливается |
| Отозван доступ к статистике | То же самое |
| Система не отдала событий | Держим последний известный пакет, таймер не прыгает |
| Сервис убит системой | `START_STICKY`, при рестарте читает prefs и восстанавливает оверлей |
| `addView` бросил исключение | Ловим, останавливаем сервис, без краша |
| Экран погас | Сессия паркуется; включил экран в пределах грации — счёт продолжается |

## Дополнение: вкладка статистики (тот же день)

Экран стал двухвкладочным: `MainActivity` держит `BottomNavigationView` и два фрагмента —
`SettingsFragment` (бывшее содержимое главного экрана) и `StatsFragment`.

Статистика берётся из системы, своя база не ведётся: `UsageStatsManager.queryAndAggregateUsageStats`
уже отдаёт суммы по пакетам и хранит их месяцами, точнее и дешевле собственного учёта.

| Решение | Обоснование |
|---|---|
| Периоды Сегодня / 7 дней / 30 дней | Сегодня — от локальной полуночи, остальные — скользящее окно от текущего момента |
| Только запускаемые приложения | Иначе список забивают системные пакеты без имени и иконки |
| Порог 1 минута | Меньше — шум |
| Загрузка в отдельном потоке | Иконки и имена тянутся через PackageManager для десятков пакетов |
| `<queries>` с `CATEGORY_LAUNCHER` | Видимость пакетов на Android 11+; `QUERY_ALL_PACKAGES` не нужен |

Строка списка: иконка, название, время (`3 ч 12 мин`), полоса доли от самого залипательного
приложения. Сверху — сумма за период. Без доступа к статистике вкладка показывает заглушку
с кнопкой выдачи разрешения.

Палитры цветов обёрнуты в `HorizontalScrollView` — восемь кружков не помещались в ширину экрана.

## Границы (чего в этой версии нет)

- Нет графиков по дням, только суммы за период.
- Нет лимитов и уведомлений «ты залип».
- Нет белого или чёрного списка приложений, кроме тумблера «прятать на рабочем столе».
- Нет виджетов и плиток быстрых настроек.
